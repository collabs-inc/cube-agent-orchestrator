# Cube port implementation plan

> Execute inline using superpowers:executing-plans, with a final independent review.

**Goal:** Run the upstream agent workspace on Cube with real machine resources.

**Architecture:** A loopback Node launcher supervises the Go daemon, serves the
renderer, and proxies same-origin API/stream traffic. An opt-in Cube renderer
adapter implements essential desktop bridge behavior without preview data.

**Tech stack:** Go daemon, Node HTTP server, React/Vite renderer, Cube manifest.

**Spec:** `docs/superpowers/specs/2026-10-10-cube-port-design.md`

## Constraints and review focus

Preserve Electron behavior, upstream licenses, and all real user state. Test
cross-origin mutation rejection, proxy stream/upgrade handling, daemon startup
failure, filesystem path validation, and shutdown of owned children only.

## Tasks

- [ ] Add launcher tests in `cube/server.test.mjs` for readiness, static serving,
  API proxy, WebSockets, origin checks, and traversal protection; observe red.
  Implement `cube/server.mjs` and `cube/start.mjs`; verify and commit.
- [ ] Add browser adapter tests for real daemon readiness and same-origin API
  routing. Implement opt-in `frontend/src/renderer/lib/cube-bridge.ts` plus
  minimal integration in bridge and daemon status. Implement remote directory
  selection and honest unsupported desktop controls. Verify and commit.
- [ ] Add reproducible `cube/install.mjs` and root `cube.json`; build daemon and
  renderer with pinned toolchains, store state outside install directory.
  Document install/update/runtime behavior and attribution.
- [ ] Run isolated browser acceptance with a temporary Git repository, a real
  daemon and terminal, and a controlled worker command. Run upstream validation
  suites where supported, record failures and unavailable platform jobs.
- [ ] Request independent review, resolve findings, commit, push, and open PR.
